# Editable layer clipping

The native Layer model now has a default-false `clipped` flag. An unclipped sibling is the base of the following clipped siblings. The base remains visible. Clipped colors blend into its isolated color while retaining its alpha, and the base's opacity/fill/style is applied to that stack. Hidden bases hide their clipped followers; orphan flags are retained and render as ordinary independent layers until an actual base exists. Group markers keep their existing painter ordering. Nested clipping constraints also govern pointer hits and mask-source transparency.

Create Clipping Mask and Release Clipping Mask use one typed transaction. A concrete context-menu owner affects that layer; a multiple-layer selection keeps the lowest selected layer as its base. Pixel canvas Ctrl/Cmd+Alt+G toggles clipping through the existing mode-aware shortcut path. Native fields keep their editing keys. Locked/busy owners and mask-reference cycles refuse without editing history. Layer-row arrows identify the current base. Shift-click selects a contiguous range of visible rows; platform-command clicks toggle whole-layer row selection. Collapsed group rows remain group targets instead of becoming only their selected descendants. Ctrl-clicking a raster thumbnail keeps the existing alpha-selection route.

Byte previews/exports and the existing authoritative float compositor use the same sibling grouping and source-atop meaning. Normal and pass-through groups retain their existing backdrop behavior, masks and styles. Float RGB/HDR/negative samples, profiles, alpha and CMYKA keep the existing native ownership and color routes. Native effects/filter combinations that already require a float effect engine remain named refusals. New clipping scratch is admitted and render errors propagate before output publication.

PSD/PSB import retains the actual clipping record bit instead of converting it into a static mask. Export writes that bit and the original editable layer pixels; its compatibility composite uses the real clipping compositor. Native project feature **35** protects the flag in current documents, embedded compositions and retained cells. Ordinary false/default layers omit it and retain their earlier required reader. This is a project-file capability, not a public application-version change.

SVG, PDF, IDML, OpenRaster and Lottie clipping export remain unfinished. These writers now refuse named clipping data instead of silently losing the relationship. Live protocol 3 likewise refuses this newer state through both canonical policies; its supported neutral/native/common/Motion behavior remains separate. Complete vector interchange and newer live capability are still work required by the overall parity goal. This layer does not declare clipping or full Craft parity complete.
