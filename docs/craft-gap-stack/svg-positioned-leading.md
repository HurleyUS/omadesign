# Leading for positioned SVG text

The native Leading field now moves authored SVG rows and columns. Both character ranges and the older whole-run property use the existing typed edit and history route. The first baseline stays fixed; subsequent baselines use the largest character leading on their line. Automatic leading uses each character's real font size. Absolute resets, relative offsets, separate columns, vertical direction, superscripts and ranges inside ligatures/combining clusters retain their source positions and ownership.

The existing shaper exposes the resolved linear pen before font baseline shifts and vertical orientation. This is a measurement, not another layout engine. Standard SVG dx/dy carries the visible edit. Bounded offset metadata retains the source offsets and native leading ranges; capture checks their length, ordering and finite values before restoration. Loaded finite values keep their raw native value and the composer's existing minimum paint spacing. A last line or a single text path has no following baseline to move; its accepted intent still survives reopen. No native model, schema, dependency, font loader or compositor is added.

Two existing renderer gaps surfaced in the independent comparison. Text-root baseline shifts now participate in the normal ancestor sum. Rotated vertical font metrics account for the rounded-descent transfer used in the tested Chromium SVG route; tiny-font metrics retain their fractional path. The primary rule is in [Chromium's font metrics implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/third_party/blink/renderer/platform/fonts/font_metrics.cc). A separate actual-browser prototype matched vertical and independently positioned/rotated text exactly at six font/size combinations. Native scaled text with relative offsets uses the existing standard text-path guide compiler, preserving logical text and original source.
